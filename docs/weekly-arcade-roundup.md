# Weekly Tree Arcade Telegram roundup

Runs inside the existing notification worker every Sunday at 19:00 America/Chicago, with calendar-based DST-safe windows ending at publication. Destination is the existing NFTree bot chat/topic, not subscriber DMs. No rewards or prize eligibility.

Independent collection every five minutes archives saved endings from Canopy Breaker and Tree Force and completed BattleUpdate / RankedBotBattleV2Update chain events. It does not use Telegram delivery history. Forward tracking begins at activation; the first report explicitly labels partial coverage. Source outages are flagged; only saved records are ranked. Tree Force still requires Save score and remains client-reported. PvP includes only recorded completed matches from the monitored event stream, never queue entries. Free practice is excluded.

Public feeds add a SHA256 wallet fingerprint, with no wallet/session/payment disclosure. Rankings use this stable identifier, not a username or anonymous label. Each score game gives one slot to each player using their best score during the window; ties use earliest achieved time then fingerprint. Battle rankings use wins, then completed matches, then fingerprint; displayed win rates use all recorded completed matches. Top three per game, full clears, earliest full-clear highlight, saved-ending/player totals, busiest game, and arcade link are included. Names prefer source SuiNS, public usernames, then a distinguishable anonymous label. Chain wallets go through the shared current SuiNS resolver before posting.

Ledger is stored in the existing atomic mode-0600 state file on the Railway volume under weeklyArcade; keep that volume attached and back up the file with the service. Results retain 35 days. Repeated unchanged endings are deduplicated; a later improved paid-continuation ending is retained as a separate saved ending, while each player still has one ranking slot. Do not treat saved-ending counts as unique purchased runs.

Publication is reserved before the API request. A successful send persists sent. Explicit Telegram API rejections release the reservation for retry. An ambiguous timeout or crash leaves uncertain/sending and prevents automatic duplicate publication. Reconcile that week in Telegram before changing its weeklyArcade.reports entry; never blindly delete it or reset all state. Missed outages send only the most recent due week on restart, not a backlog of posts. Existing individual alerts remain active.

Validation: weekly fixtures cover DST, boundary inclusion, duplicate/changed names, anonymous identities, continuation score snapshots, battle wins/losses, PvP participants, outage labels, restart deduplication, API retry and ambiguous delivery. Existing notifier regression tests and server bundle also pass.
